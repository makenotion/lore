# CLI Historical Evidence

This archive preserves historical breadcrumbs removed from the current CLI
subsystem guide during the guide split. The active implementation contracts now
live in [`../cli-authoring.md`](../cli-authoring.md) and
[`../cli-command-contracts.md`](../cli-command-contracts.md).

## Removed Breadcrumbs

| Area                         | Historical breadcrumb removed from active guidance                                                                                          | Current invariant kept in active docs                                                                                                                                                                 |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Exit-path tests              | Earlier reviews established the no-throw `trapProcessExit` pattern after throw-sentinel helpers produced doubled errors in command actions. | New command exit tests use `trapProcessExit`, assert `toEqual([1])`, and pair early exits with defensive `return`.                                                                                    |
| Auth / install rollout       | The `ntn` detection, auto-install, vault preflight, and MCP env-forwarding behavior landed across multiple rollout slices.                  | `lore install` is PAT-first by default; `--ntn` opts into the internal-engineer flow; MCP children resolve auth at startup and receive static config-root values only for host shapes that need them. |
| Agent normalization          | Internal vault audits found several Claude spelling variants during the agent-identity rollout.                                             | Write-time canonicalization owns the variant table; migration flags canonicalize historical rows only.                                                                                                |
| Synopsis backfill            | The synopsis migration was introduced for rows that predated the Synopsis property.                                                         | Discovery targets empty Synopsis values and apply mode is idempotent; the placeholder backend writes a sentinel and skips body fetches.                                                               |
| Confidence backfill          | Confidence scoring shipped after older rows already had categorical confidence values.                                                      | The migration seeds numeric confidence from categorical confidence, initializes a decay anchor, and skips rows that already have a numeric score.                                                     |
| Status proposed-memory count | The proposed-memory inbox originally shipped as a multi-surface feature.                                                                    | `lore status` surfaces pending proposed memories through shared core loaders and renderers; empty inboxes remain silent in status output.                                                             |
| Conflict scan caps           | The conflict scanner design separated candidate-generation coverage from prompt budget after earlier drafts conflated the two.              | `--raw-limit` controls coverage before filtering; `--limit` controls rendered prompt budget after deduplication and filtering.                                                                        |
| Mine summary compatibility   | `lore mine` gained update counts after the original indexed-file summary existed.                                                           | Fresh-vault output remains byte-stable; update counts are appended only when at least one update landed.                                                                                              |
