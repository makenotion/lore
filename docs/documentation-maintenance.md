# Documentation Maintenance

This page plans focused splits for oversized Lore docs and agent guides. It is
an inventory and routing plan only: the source files listed below remain
authoritative until a follow-up PR moves their content and updates links.

## Split rules

- Keep root `AGENTS.md` and subsystem `AGENTS.md` files as routing guides with
  current instruction precedence stated up front.
- Keep current contracts in the routing file or in a linked child doc that the
  routing file names as authoritative for that subsystem.
- When a future split adds child docs under a subsystem, the subsystem
  `AGENTS.md` must gain a short child-doc routing table in the same PR. That
  routing entry is what keeps the moved contract under the subsystem's
  instruction precedence.
- Move release notes, phase evidence, dated verification logs, and closed issue
  history into `history/` docs. Historical docs are reference material and must
  not be the only place a live `MUST`, `NEVER`, or operator contract appears.
- Split one source file per PR unless the files are mechanically linked by the
  same cross-reference update.
- Preserve headings and anchors when possible. When an anchor must change, add
  the replacement link in the routing file in the same PR.

## Recommended first split

Start with `src/notion/runtool/README.md` and extract
`src/notion/runtool/docs/history/phase-4-default-on.md`.

Reasons:

- It has the clearest current-vs-historical conflict: the README includes both
  landed default-on language and a `Phase 1+ pending` heading.
- The evidence log is already a contiguous section, so the PR can be mostly a
  move plus link repair.
- The routing README can keep the live default-on, disable-flag, and rollback
  contracts in place, preserving operator guidance.

## Verification for split PRs

For this planning issue, run the bounded line-count inventory from the issue:

```sh
wc -l README.md AGENTS.md docs/*.md src/*/AGENTS.md src/notion/runtool/README.md
```

Every follow-up split PR should also run a broader Markdown inventory so nested
child docs account for moved lines:

```sh
find README.md AGENTS.md docs src -type f -name '*.md' -print | sort | xargs wc -l
rg -n "current contract|historical|history/" docs src/*/AGENTS.md src/notion/runtool/README.md
```

For the planning PR that adds this file, the bounded line-count check should
show only a small increase for `AGENTS.md`, `docs/development.md`, and this new
plan. For content-moving PRs, the broader inventory should show the source file
shrinking and the new child docs accounting for the moved lines.
